# GoreeCloud Metrics — verified browser UI token bridge

**State: partial alpha source adoption; NOT a release, founder visual signoff, native adoption, or comprehensive supported-browser qualification.** Review performed November 20, 2026 against the protected GoreeCloud UI alpha source `be8b819748d1ef0f6b2d3e786f4b22864cb3d07d`.

Metrics retains its purpose-built infrastructure-monitoring navigation, systems, alerts, real CPU/history charts and private hub access flow. It originally copied light/dark Lagoon values as literal hexes in its own stylesheet. This change imports the **real first-party** `src/tokens.css` from the verified upstream `GoreeCloud/gc-ui` revision, preserving MIT attribution and pinning the exact CSS and license hashes in `web/src/vendor/gc-ui/provenance.json`. The existing Metrics-specific `--canvas`, `--brand`, `--text` etc. aliases now resolve from central semantic roles, with `data-gc-accent="lagoon"` on the Metrics web document. Automatic OS dark/light, high-contrast and reduced-effects tokens are delegated to the shared CSS. The primary submit action correctly uses the token's **on-brand** foreground rather than a hard-coded surface color. No new package, network request, account, secret persistence, API, native code, or database migration is introduced.

## Actual verification

- React TypeScript/Vite production build: **PASS**. Two Node source/attribution tests: **PASS**; the locked dependency install used `--ignore-scripts`.
- **Real headless browsers:** Chromium 159.0.8154.6, Firefox 159.0 and Linux WebKit 27.2 each opened the actual local Vite **development sign-in screen** in three conditions: desktop 900×800 light, mobile 390×844 system dark, compact 320×760 light. **9/9 scenarios PASS**. Each verifies the accessible `Administrator access token` label, keyboard Tab reaching `Connect to hub`, expected Lagoon accent, matching OS appearance, primary action contrast at least 4.5:1, the login panel within viewport, no document horizontal overflow, no uncaught page errors and no external requests. Measured primary-button contrast: **6.36:1** light and **8.79:1** dark across all three engines.
- Real snapshots inspected from development login only: [WebKit desktop light](evidence/metrics-webkit-desktop-light.png) and [Chromium dark mobile](evidence/metrics-chromium-mobile-dark.png). The token field was **empty**, and no hub login or API request was made. Screenshots are not permission to publish UI or evidence of actual monitoring data.
- `web/test/browser-acceptance.mjs` is an opt-in, **no-download, no-authentication** acceptance runner, intentionally not a mandatory CI browser job without maintained engine binaries. To reproduce, start the local source server: `cd web && npm ci --ignore-scripts && npm run dev -- --port 18750 --strictPort`. In another terminal, from `web/`, supply explicit absolute paths to inspected `GC_PLAYWRIGHT_CORE_MODULE`, `GC_CHROMIUM_BIN`, `GC_FIREFOX_BIN`, `GC_WEBKIT_BIN`, then `npm run browser:acceptance`. The runner permits only loopback requests to port 18750 and fails closed when binaries are missing. Optionally supply an existing absolute `GC_QA_SCREENSHOTS_DIR` to capture fixture-only screens.

### Physical Android web spot-check (additional evidence)

On a consenting, already-authorized USB-connected **OnePlus N200 (DE2117), Android 16**, the actual local Metrics sign-in page loaded through a temporary, loopback-only ADB reverse tunnel in **Android Chrome 157.0.8103.78 and Firefox 160.0.1**. Android's accessibility hierarchy exposed the visible `See every system.`, `Administrator access token`, and `Connect to hub` labels in both browsers; Firefox required one bounded page-load retry before the UI was present. The [cropped real Chrome phone screenshot](evidence/metrics-android16-chrome-physical.png) shows only the empty development sign-in state, with browser chrome, status and gesture areas removed. No login, private system data, personal notifications, password or service API calls were involved. **This is physical consumer-WEB page visibility, not human TalkBack or a Flutter Android app test.** Temporary tunnel/test XML/server are to be removed immediately after acceptance; phone accessibility preferences remain unchanged.
