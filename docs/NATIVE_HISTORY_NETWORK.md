# Native Linux/Android monitoring detail improvements

The Flutter client now offers a Material 3 segmented control for six-hour, 24-hour (default) and seven-day history. The selected host's 400-point bounded aggregate history is requested over the existing HTTPS-required hub connection. Late results for a prior host or period are ignored; the chart is cleared immediately when the selection changes. The native client also requests the administrator-authenticated per-host network rate through its existing redirect-refusing, response-size-bounded HTTP client. Receive and transmit byte rates are displayed only when the API reports an OK interval; insufficient samples, invalid/stale readings and counter resets show explicit, nonnumeric states.

Both features use the canonical pinned GoreeCloud Flutter Material 3 theme, existing in-memory credentials, and native widgets. Changes do not enable location tracking, notifications, containers, new permissions, persistent tokens or external cloud telemetry. Unit/widget tests and analyzer checks exercise the source; real Linux desktop accessibility, physical Android installation and user acceptance remain unverified. No owner device or production service was modified.
